# Капитал: уведомления об изменении сигналов

Раз в сутки проверяет BTC, ETH, курс ЦБ, иену и Nasdaq. В обычный день
**не присылает ничего**. Сообщение приходит только при входе в ценовое
условие или выходе из него. При первом запуске новая версия лишь запоминает
текущее состояние, чтобы не повторить старые сигналы.

Недельное закрытие BTC/ETH, потоки ETF, сделки Strategy, BitMine и Urals
пока не включены в автоматические рекомендации: прежний скрипт не проверял
их составные условия. Панель 23.09 одновременно предлагала ускорить и
притормозить крипто-транши. Бот теперь сообщает факт изменения и вопрос
для проверки, а не команду совершить сделку.

Состояние хранится в `STATE_PATH` и записывается атомарно. При сбое
мониторинга отправляется одно техническое предупреждение; успешная проверка
сбрасывает этот флаг. Проверка: `python3 -m unittest -v test_signals.py`.
Разовый полный статус: `SEND_STATUS=1 python3 digest.py` при настроенных
переменных Telegram. Постоянная команда `/status` требует отдельного
Telegram-обработчика и в текущем cron-сервисе отсутствует.

Сейчас крутится на Маке через launchd. Проблема: если компьютер спит или не в сети
к 09:45 — сводки нет. За август так пропало 5 дней. На Railway этого не будет.

Разворачивается **в тот же проект Railway, где живёт task-bot** — тем же способом,
через GitHub и автодеплой.

---

## Шаг 1. Создать репозиторий на GitHub

Открыть <https://github.com/new> под аккаунтом `ph3dnru-creator`:

- **Repository name:** `market-signals`
- **Private** — обязательно
- Ничего не добавлять (ни README, ни .gitignore) — всё уже готово локально

Нажать **Create repository**.

## Шаг 2. Залить код

В Терминале:

    cd /Users/artem/Documents/market-signals-railway
    git remote add origin https://github.com/ph3dnru-creator/market-signals.git
    git branch -M main
    git push -u origin main

## Шаг 3. Добавить сервис в Railway

На railway.com открыть **тот же проект**, где task-bot →
**+ New** → **GitHub Repo** → выбрать `market-signals`.

Railway соберёт его сам (Nixpacks увидит `runtime.txt` и `requirements.txt`).
Первый деплой упадёт с ошибкой про переменные — это нормально, они на шаге 4.

## Шаг 4. Прописать переменные

Сервис `market-signals` → вкладка **Variables** → добавить три:

| Переменная | Значение |
|---|---|
| `TG_TOKEN` | токен бота @Capital_art_bot от BotFather |
| `TG_CHAT_ID` | `150462912` |
| `STATE_PATH` | `/data/state.json` |

Это **другой бот**, не @x10_tasks_bot. Токен лежит в старом скрипте на Маке:
`/Users/artem/Scripts/market-signals/digest.py`, строки 10–11.
После переноса оттуда его стоит удалить — в облаке он уже будет в Variables.

## Шаг 5. Подключить диск

Сервис → **Settings** → **Volumes** → **New Volume** → путь `/data`.

Диск хранит `state.json` — последнее состояние каждого условия. Без него
бот не сможет отличать новое изменение от уже известного состояния.

## Шаг 6. Поставить расписание

Сервис → **Settings** → **Cron Schedule**:

    45 6 * * *

06:45 UTC = **09:45 по Москве**. Railway живёт по UTC — это единственное место,
где легко ошибиться.

При включённом расписании Railway запускает контейнер, тот отрабатывает
за секунды и выключается. Отдельный сервис за это почти ничего не добавляет
к вашему текущему счёту.

## Шаг 7. Проверить

**Deployments** → у последнего деплоя **View Logs**. Ждём строку:

    OK: проверено ...

При неизменных условиях сообщения в Telegram не будет. Не дожидаясь утра,
запустить проверку можно кнопкой **Redeploy**.

---

## Когда заработает — выключить Мак-версию

Иначе могут приходить дублирующие сообщения:

    launchctl unload ~/Library/LaunchAgents/com.artem.market-signals.plist

Вернуть обратно, если что-то пойдёт не так:

    launchctl load ~/Library/LaunchAgents/com.artem.market-signals.plist

## Как менять потом

**Пороги ценовых условий** — в `signals.py`, список `RULES`.
Правим → `git commit` → `git push` → Railway задеплоит сам, как у task-bot.

**Время отправки** — Cron Schedule в настройках сервиса. Помним про UTC.

## Что проверить после первого запуска

Скрипт ходит на `cbr.ru` за официальным курсом доллара. Сайт российский,
Railway — зарубежный хостинг. Если в логах будет ошибка именно на курсе,
значит ЦБ не отдаёт данные с иностранного адреса — тогда переключим
на биржевой курс, это пять минут.

## Сборщик постов (`collector.py`)

Второй сервис в этом же репозитории. Отдаёт свежие посты отслеживаемых Telegram-каналов
простым текстом по адресу `https://<домен>/<FEED_TOKEN>`.

Зачем: облачный агент-разборщик не может открыть `t.me` — домен закрыт политикой сети его
окружения. Railway такого ограничения не имеет.

Настройки сервиса: конфиг `railway.collector.json`, переменная `FEED_TOKEN`, публичный домен.
Состояние не хранится — посты забираются в момент запроса.
